# Init Command

**Status:** Done | **Owner:** main-agent | **Updated:** 2026-08-06 23:34

## Goal

Add `surfy init`, operating on the current directory, to detect a supported project layout and safely create a minimal `surfy.yaml`.

## Scope

- Detect supported apps in common `frontend`/`web`/`client` and `backend`/`api`/`server` directories.
- Detect a supported root Node application as `web`, or root Python/Go application as `api`.
- Generate only `web` and/or `api` shorthand entries.
- For confidently detected FastAPI projects, generate the concrete venv/uvicorn command and an `ENV_FILE` reference when `.env` exists.
- Add concise comments explaining generated paths, automatic ports, and `.env` handling.
- Refuse arguments, unsupported/ambiguous layouts, and an existing `surfy.yaml`.
- Update CLI help and user documentation.

## Affected Files

- `internal/scaffold/init.go`
- `internal/scaffold/init_test.go`
- `internal/app/app.go`
- `README.md`

## Test Strategy

- Test-first coverage for split frontend/backend discovery, root discovery, existing-manifest protection, and unsupported layouts.
- Full formatting, vet, test, and Apple Silicon build verification by a separate test runner.

## Definition of Done

- [x] `surfy init` creates the expected manifest in the current directory.
- [x] Existing files are never overwritten.
- [x] Errors are actionable for unsupported or ambiguous layouts.
- [x] CLI help and README document the command.
- [x] Full suite and native ARM64 build pass (20/20 tests).
